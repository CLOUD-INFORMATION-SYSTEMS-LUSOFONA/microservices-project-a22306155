🎓 CONCEITOS-CHAVE

Branch Strategy:
  ├─ Feature branches → terraform-plan.yml (validação)
  ├─ Main branch → terraform-apply.yml (produção)
  └─ Nenhum apply manual (sempre via GitHub Actions)

Workflow Triggers:
  ├─ terraform-plan.yml: Pull Request (infra/terraform/ changes)
  ├─ terraform-apply.yml: Push para main (infra/terraform/ changes)
  ├─ ansible-config.yml: workflow_run (terraform-apply sucesso)
  └─ ansible-deploy.yml: workflow_run (ansible-config sucesso)

Outputs Capturados:
  ├─ ec2_public_ip: 1.2.3.4
  ├─ rds_endpoint: db-*.eu-central-1.rds.amazonaws.com
  └─ sqs_queue_url: https://sqs.*.amazonaws.com/...

Variáveis Injectadas:
  ├─ RDS_ENDPOINT (para applicação)
  ├─ DB_PASSWORD (credenciais banco dados)
  └─ SQS_QUEUE_URL (para processamento mensagens)

❓ PERGUNTAS FREQUENTES

P: Preciso fazer algo manualmente?
R: Não! Tudo é automático. PR → Merge → Deploy automático.

P: Quanto tempo demora tudo?
R: PR validation: 2-3 min | Deploy: 10-12 min total

P: Como faço rollback?
R: git revert <commit> + push para main. Terraform automaticamente reverte.

P: Onde vejo os logs?
R: GitHub Actions tab → Selecionar workflow → Ver logs detalhados

P: Posso ver o plan antes de apply?
R: Sim! PR comment mostra plan. Review antes de merge.

P: O que acontece se terraform-apply falha?
R: Workflow para, GitHub notifica, nada é deployado. Fix e retry.
