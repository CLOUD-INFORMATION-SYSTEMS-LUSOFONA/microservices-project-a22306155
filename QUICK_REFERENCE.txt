```
Valida: Health endpoints
Duração: 4-5 minutos
```

#### ✅ JÁ EXISTE - `.github/workflows/terraform-plan.yml`
```
Roda em: Pull Requests com changes em infra/terraform/
Valida: fmt, init, validate, plan
Comenta: Resultado no PR
Bloqueia: Se falhar (nenhum apply)
Duração: 2-3 minutos
```

#### ✅ JÁ EXISTE - `.github/workflows/terraform-apply.yml`
```
Roda em: Push para main com changes em infra/terraform/
Aplica: terraform apply -auto-approve
Deploy: Executa ansible playbooks
Verifica: Health endpoints dos serviços
Duração: 10-12 minutos total
```

## 🚀 Fluxo Simplificado

```
git checkout -b feature/xxx
  ↓
Make changes in infra/terraform/
  ↓
git push origin feature/xxx
  ↓
Create Pull Request
  ↓
terraform-plan.yml roda automaticamente (2-3 min)
  ↓
Review plan no PR comment
  ↓
Approve PR
  ↓
Merge para main
  ↓
terraform-apply.yml roda automaticamente (10-12 min)
  ├─ Job 1: terraform apply
  ├─ Job 2: ansible playbooks
  └─ Job 3: health checks
  ↓
🎉 Environment em Produção!
```

## ✨ Principais Features

✅ **Automação Completa**
- PR validation automática
- Infrastructure deployment automático
- Application deployment automático
- Zero manual steps

✅ **Segurança**
- OIDC (sem AWS keys)
- GitHub Secrets
- SSH key management
- State file locking

✅ **Rastreabilidade**
- Tudo em Git (commits)
- Tudo em GitHub Actions (logs)
- Tudo em AWS CloudTrail (audits)

✅ **Rollback Simples**
- git revert → terraform reverte

✅ **Modular**
- Workflows separados
- Fácil de estender
- Fácil de manter

## ❓ Dúvidas Rápidas

**P: Preciso fazer terraform apply manualmente?**
A: Não! Sempre via GitHub Actions.

**P: Como vejo os logs?**
A: GitHub.com → Actions tab → Selecionar workflow

**P: Quanto tempo demora?**
A: PR: 2-3 min | Deploy: 10-12 min

**P: Como rollback?**
A: git revert + push para main

**P: Onde estão os secrets?**
A: GitHub Settings → Secrets and variables → Actions
